# ゲームルール共有仕様

この文書は、A〜Dが並列実装するときに参照するゲームルールの正本である。数値、判定順、失敗時の状態を実装ごとに変更してはならない。

## 1. ゲームの単位

- 1ゲームは最大4人で遊ぶ。開始時に人間参加者が4人未満の場合、空席をCPU参加者で埋める。
- 盤面はマスID `1`〜`100` の100マスとする。マス1は入学、マス100は卒業判定地点である。
- プレイヤーは同じ盤面を進み、マス100を超えて移動しない。
- ゲーム内の月は1から始まり、最大4年分の48か月を基本期間とする。留年した場合は、留年期間の月を追加して進める。
- 1ラウンドは卒業していない参加者が1回ずつ手番を行う。卒業済み参加者は飛ばす。参加者の順序はゲーム開始時に確定し、以後は時計回りで固定する。

## 2. 初期状態と経済

| 項目 | 確定値・規則 |
| --- | --- |
| 初期位置 | マス1 |
| 初期単位 | 0単位 |
| 初期学力 | 50 |
| 初期人脈 | 0 |
| 初期所持金 | 10,000円（10000円） |
| アルバイト収入 | 月20,000円（20000円）。行動の解決時に加算 |
| 年部費 | 3,000円（3000円）。サークル参加者が年度開始時に支払う |
| 所持金の下限 | 0円。所持金を負数にしない |

年度開始は月1、13、25、37、および留年後の各年度の開始月とする。サークルに未参加の人からは部費を徴収しない。

- 未参加者がサークルを選び、所持金が3,000円以上なら、3,000円を支払って参加する。
- 未参加者が3,000円未満でサークルを選んだ場合、入部せず、所持金と人脈を変更しない。ただし、その月の行動権は消費する。
- 参加者が年度部費3,000円以上を持つ場合は支払い、参加状態を維持する。
- 参加者が年度部費を支払えない場合は徴収せず、サークルから退部させる。退部しても、それまでに得た人脈は減らさない。

年度部費は年度開始時にサークル参加者から1回だけ徴収する。サークルを選んだ未参加者の入部時支払いは入部処理であり、年度部費とは別である。例えば月1に初めてサークルへ入部した場合は入部時に3,000円を支払うが、同じ月の年度開始処理では再度徴収しない。翌月以降の月次行動でも年度部費は徴収しない。

## 3. 月次行動と学力

1か月に選べる行動は1つだけである。行動の効果は次のとおり。

| 行動 | 効果 |
| --- | --- |
| 勉強 | 学力 `+10` |
| サークル | 人脈 `+1`。未参加者は部費を支払って入部できた場合のみ加算 |
| アルバイト | 所持金 `+20,000円` |

勉強を選ばなかった月は、行動の解決後に学力を `-2` する。サークルまたはアルバイトで部費処理が発生しても、この忘却は適用する。勉強による増加と忘却の両方を同じ月に適用しない。

- 学力の初期値は50、下限は0、上限は100。
- 学力の増減後は必ず `0〜100` に丸める。
- 人脈は0以上の整数で、上限を設けない。
- 同じ月に複数の行動を実行できない。

学力は状態として保存・表示し、月次行動で増減する。現行の科目合否では学力を計算に使わない。科目の基礎合格率は50%、過去問を入手した科目は70%（50%+20ポイント）とする。この固定式を変更する場合は、後続実装IssueのACを更新してから合意する。

## 4. 交流と過去問

### 4.1 交流成功率

交流イベントを実行する場合の成功率は、次の式で決める。

`交流成功率 = min(95%, 50% + 人脈 × 5%)`

乱数は0以上1未満の一様乱数を1回だけ生成し、乱数が成功率未満なら成功とする。成功時は人脈を1増やし、失敗時は状態を変更しない。成功率は0%未満にも100%超にもならない。

交流イベントは、到着マスの種別が `EVENT` のときに発生する。現在の盤面ではマス10、20、30、40、60、70、80、90を交流マスとする。マス50は試験マスであり、交流イベントを発生させない。イベント結果は成功・失敗と人脈の増減を保存する。

### 4.2 過去問の入手

半期末の各科目について、次の式で過去問の入手可否を判定する。

`過去問入手率 = min(100%, 人脈 × 10%)`

科目ごとに独立した乱数を1回生成する。過去問を入手できた科目には、合格率補正 `+20ポイント` を付ける。

### 4.3 科目の合否

- 1半期の履修数は8科目。
- 1科目は2単位。1半期で最大16単位を得る。
- 科目合格率は基礎50%に過去問補正を加えて算出する（過去問なしで50%、過去問ありで70%）。
- 科目ごとに独立して合否を判定し、合格した科目だけ2単位を加算する。
- 合否判定は6か月目、12か月目、18か月目、24か月目、30か月目、36か月目、42か月目、48か月目、および留年中の各6か月終了時に行う。
- 半期の判定順は、履修科目の確定、過去問入手判定、科目別合否、単位加算、卒業・留年判定の順とする。

## 5. サイコロ、手番、月の進行

各月は、卒業していない参加者だけが手番を行う。人間参加者とCPU参加者は同じ手番順・同じ状態更新規則で処理する。各参加者の手番は必ず次の順で処理する。

1. 現在の月と手番参加者を確認する。
2. 手番参加者が月次行動を1つ選ぶ。人間は画面から選び、CPUはサーバーのCPU行動選択処理が選ぶ。
3. 行動の効果、忘却、必要な部費を解決する。
4. 6面サイコロを1回振る。
5. 出目のマス数だけ進む。通常在籍中はマス100を超える分を切り捨て、位置を100にする。留年中はマス91〜100の周回規則を適用する。
6. 到着マスのイベントを解決する。
7. 次の未卒業参加者へ手番を移す。卒業済み参加者は飛ばす。

全未卒業参加者の手番が終わったら、該当する場合だけ半期判定を行い、その後に月を1進める。月6、12、18、24、30、36、42、48、および留年中の6か月終了時は、月を進める前に半期判定を1回だけ行う。半期判定は全員の行動・移動・到着イベントの後に行う。年度部費の処理は月末には行わず、月1、13、25、37、および留年後の各年度開始月の最初の手番の前に1回だけ行う。サイコロの出目はサーバーが生成し、クライアントから指定できない。

CPUの行動選択はサーバー内部で行い、優先順位は、学力が50未満なら勉強、そうでなく人脈が5未満かつ入部可能ならサークル、それ以外はアルバイトとする。CPUの行動・サイコロ・イベント処理は、人間の操作要求を必要とせず、ゲーム進行サービスがCPU手番の開始時に1回だけ実行する。人間またはCPUの処理後に次の手番がCPUなら、ゲーム進行サービスは次の人間の手番または `FINISHED` になるまでCPU手番を連続実行する。

## 6. 卒業、盤面終点、留年

- 卒業に必要な単位は124単位以上。
- 初回のマス100到着は卒業判定対象となる履歴を作る条件であり、到着だけでは卒業にならない。履歴作成後は現在位置を問わず半期判定の対象とする。
- 初めてマス100に到着したとき、`hasReachedGoal` をtrue、`firstGoalMonth` に到着月を保存する。以後は現在位置にかかわらず、到達履歴が卒業判定の対象条件となる。
- 半期判定では、`hasReachedGoal` がtrueの参加者を対象に単位を確認する。月24末にマス96であっても、過去にマス100へ到達済みで124単位以上なら卒業する。
- 到達履歴があり、単位が123以下なら、その半期判定で留年状態にし、`repeatYears` を1増やす。`repeatYears` は暦年数ではなく、単位不足で留年した半期判定の回数を表し、各判定で1回だけ増やす。
- 留年中も毎月1回の行動、サイコロ、月の進行を行う。留年者は周回区間のマス91〜100を移動し、マス100を超えた出目はマス91へ戻して残りの出目を続ける。これにより、留年中も到着イベントを発生させる。
- 留年中にマス100へ到着しても、その場では卒業せず、直後の半期判定で単位条件を確認する。単位が不足している場合は周回を続ける。
- 留年中も6か月ごとに8科目の履修・合否判定を行う。単位が124以上になった次の判定で卒業する。
- 卒業済みの参加者は行動・サイコロ・月次効果の対象外とする。
- 判定済みの半期を同じリクエストで再処理しない。卒業・留年状態と単位は、判定結果として保存する。

半期判定で全参加者が卒業済みになった場合、同じトランザクションでゲーム状態を `FINISHED` に変更し、`currentPlayerNumber` を0にする。全員卒業時は月を進めず、判定を行った月を保持する。未卒業者が残る場合は `PLAYING` のまま次の月へ進める。

## 7. 卒業順位と同順位

- 卒業順位は卒業が確定した順に決める。複数人が同じ半期判定で卒業した場合は、単位数の多い順、留年回数の少ない順、同じ場合はその半期の手番順で順位を決める。
- 同順位は認めず、順位決定の比較キーが同じ場合は開始時に確定したPlayerNumberの小さい順で決める。
- 卒業順位は `graduationRank` として参加者状態に保存する。未卒業者は `0` とし、卒業後は変更しない。
- 結果画面では卒業順位、表示名、単位数、留年回数を表示する。`FINISHED` では全員卒業済みであり、未卒業者は結果確定前のゲーム画面にのみ表示する。

## 8. 状態遷移の失敗規則

- 不正な参加者ID、現在の手番でない参加者、終了済みゲームへの操作は拒否し、状態を変更しない。
- 月次行動、サイコロ、半期判定は同じ手番・同じ月に二重適用しない。
- 部費不足はエラー終了ではなく、上記の入部不可または退部として通常のゲーム結果にする。
- 乱数の結果をクライアントから受け取らない。再試行時は同じ処理を二重に適用せず、保存済み結果を返す。
